# A/B-тест нового алгоритма рекомендаций (Python, статистика)

## Описание проекта
Развлекательное приложение с «бесконечной» лентой коротких видео зарабатывает на платной подписке без рекламы и на показе рекламы пользователям без подписки. Команда рекомендательных систем разработала новый алгоритм, который, по её мнению, показывает пользователям более интересный контент.

**Цель:** рассчитать параметры A/B-теста, проверить корректность его проведения и оценить, улучшает ли новый алгоритм вовлечённость новых пользователей.

**Данные:** сессии пользователей приложения — исторические данные за 11.08–23.09.2025 (~436 тыс. сессий), первый день теста (14.10.2025) и весь период теста (14.10–02.11.2025).

**Что сделано:**
- исследовательский анализ: динамика активных и зарегистрированных пользователей, распределение числа просмотренных страниц в первой сессии;
- выбор целевой метрики — доля успешных первых сессий (4 и более просмотренных страниц) — и оценка её базового уровня;
- расчёт размера выборки под относительный MDE (`statsmodels`, `NormalIndPower`) и длительности теста по историческому трафику;
- мониторинг теста по первому дню: размер групп, пересечения пользователей, однородность групп по устройствам и регионам;
- формулировка гипотез, прокси- и барьерных метрик;
- проверка результата односторонним z-тестом для долей (α = 0,05) и оценка чувствительности теста через доверительный интервал разницы.

**Инструменты:** Python, pandas, matplotlib, statsmodels, Jupyter Notebook.

## Выводы
- **Базовый уровень целевой метрики** — около **31%** успешных первых сессий, метрика стабильна по дням (колебания в пределах ~2 п.п.).
- **Параметры теста:** чтобы поймать относительный рост метрики на 3% (с 30% до 30,9%) при α = 0,05 и мощности 0,8, нужно **41 041 пользователь в группу**. Расчётная длительность — 9 дней по общему трафику, но в тест попадают только новые пользователи, поэтому реальный набор займёт около 19 дней.
- **Тест прошёл корректно:** группы отличаются по размеру на 0,74%, пересечений пользователей нет, структура по устройствам и регионам совпадает (расхождения до ~2 п.п.). Доли считались по уникальным пользователям — расчёт по сессиям давал ложный перекос по регионам до 6 п.п.
- **В тесте участвовали 30 579 пользователей** (15 163 в группе A, 15 416 в группе B) — около 37% от необходимого объёма, поэтому тест недостаточно чувствителен для эффекта в 3%.
- **Новый алгоритм не улучшил метрику:** доля успешных первых сессий — 31,57% в группе A и 31,47% в группе B (разница −0,11 п.п.). Z-тест: z = −0,198, **p-value = 0,578** — оснований отвергнуть нулевую гипотезу нет. 95%-й доверительный интервал разницы (от −1,15 до +0,94 п.п.) включает и ноль, и целевой эффект, так что рост на 3% по этим данным нельзя ни подтвердить, ни исключить.

**Рекомендации:** не внедрять алгоритм в текущем виде — данных в пользу улучшения нет. Если рост на 3% важен для бизнеса, продлить тест до ~41 тыс. новых пользователей в каждой группе; параллельно проверить прокси-метрики и отдельные сегменты аудитории.
